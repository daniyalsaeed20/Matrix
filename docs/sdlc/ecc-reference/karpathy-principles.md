## Four principles (summary)

1. **Think before coding** — inspect existing code; surface material ambiguity/tradeoffs; ask only when it matters; decide minor details.
2. **Simplicity first** — smallest clear solution; no speculative layers; keep production requirements.
3. **Surgical changes** — touch only the task; clean your orphans; report unrelated debt.
4. **Goal-driven execution** — verifiable AC; run checks; report what was verified; no false “tests passed.”

## Working signals

- Diffs contain only requested work  
- Fewer rewrites from overcomplication  
- Clarifying questions come **before** wrong implementation  
- Patch ceremony stays lighter than module/product ceremony
